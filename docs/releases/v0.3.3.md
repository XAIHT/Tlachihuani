# Tlachihuani 0.3.3 · Pre-release

**Current pre-release: 0.3.3.** Documentation updated 11 November 2026, as requested
by Angela López Mendoza. This version documents the Torrenter recovery work and
workspace improvements alongside the existing Windows installer and XT controls.

## Downloads that remain understandable and recoverable

- **Stalled-slot rotation:** two transfers per account and four per host remain
  the limits. An unfinished running transfer with no payload progress for
  180 seconds yields only when another eligible queued job is blocked. Partial
  files and running intent remain intact; retry waits at least 60 seconds and
  goes behind waiting work. Progressing, stopped, paused, checking, verifying
  and finished jobs are not rotated. Metadata lookup has a separate queue.
- **Accurate completion:** a completed download remains completed when its peer
  session stops. Cleared historical errors do not masquerade as current failures;
  actual transfer errors and delivery failures remain visible.
- **Safe recovery:** Start continues an incomplete stopped job, Resume continues
  a paused one, and Recheck validates retained pieces after a failure. Rapid
  Stop/Start releases the old handle before reopening. Mixed selections skip
  ineligible records and report the count.
- **Disk verification:** publication waits for libtorrent's disk-complete pause
  alert before calculating SHA-256. A missing acknowledgment reports a bounded
  recoverable failure; label/revision changes retain the acknowledgment.

## An organized workspace for each account

All twelve data columns sort in both directions; Select remains fixed. Shift-click
adds sorting priorities. Search, combined filters, progress ranges and pagination
cover the whole queue, including records after the first API page. Column
visibility/order/width, row density and detail height are saved per account and
browser. Keyboard controls and 320/390/1600-pixel layouts have visible test evidence.

The signed-in account stays in the heading. The workspace uses Tlamatini's login
and CSRF protection without asking for pairing codes. Empty/truncated session
responses receive at most two retries, spaced 200 ms apart. Download commands
are not automatically repeated. The matching English and Spanish clients explain
recovery actions and historical errors in their own language.

Verified output identifies the actual destination and hashes. Windows Downloads
is the normal final destination; `content_generated/Torrenter` is the fallback
when Downloads is unavailable. A verified private service copy alone does not
prove successful delivery. Remove record retains files; Erase files requires
the existing exact-file review and XT approval.

## Installation and packaging

The expected matching archive is `Tlachihuani-0.3.3-windows-x64.zip`, with its
`.zip.sha256`. Extract everything, open `START-HERE.html`, then run Installer.exe
and confirm **0.3.3** on Review. Follow the [setup guide](../../packaging/setup/README.md).
The package design carries private runtimes and native Windows uninstall registration.

Setup offers optional XT startup at Windows sign-in, always supplies Start/Desktop
shortcuts, and leaves both services stopped/Manual. Starting XT never starts
services. The operator selects **Start Services**; **Stop Services** leaves only
the gray tray. Uninstall retains delivered files, protected identities and job
history. Existing installations use their matching removal path; in-place wizard
upgrades are not offered.

`Build-Release.cmd` selects the highest numeric local tag and generates the ZIP in
`dist`. For this version it must select `v0.3.3` or `0.3.3`. Mark the GitHub release
as **pre-release** when publishing; the builder ignores suffixed tags. See
[release building](../release-building.md). This documentation update does not
change product metadata, create tags, build installers or publish files.

## Evidence and remaining acceptance

The [10 November verification record](../verification/2026-11-10-torrenter-recovery.md)
contains **64 passing automated checks**, **48 passing headed-browser checks**,
four real local-peer payload transfers and a separate read-only audit matching
**432 delivered files across 21 completed jobs**. The three unfinished installed
jobs were left unchanged. Those results describe the tested source and existing
files, not an installed 0.3.3 package.

Windows package acceptance still needs its own authorized build and clean-machine
installation, both startup choices, reboot, ordinary-user XT launch, service
lifecycle, file delivery and Control Panel removal. Signing, rollback, cross-account
and long-running transfer qualification remain separate gates. Updating only
Tlamatini cannot install the shared Jobs engine fixes, and updating only Jobs
cannot replace either Tlamatini executable.

The [11 November documentation verification](../verification/2026-11-11-documentation.md)
records the corrected source checkout, existing version metadata and documentation checks.

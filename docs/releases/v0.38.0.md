# Tlachihuani 0.38.0

**Latest version: 0.38.0.** Documentation updated 21 November 2026, as requested
by Angela López Mendoza. This version carries forward everything in
[0.37.0](v0.37.0.md) and adds a verbose trace log that stays quiet while
Tlachihuani is idle.

## One trace log for every process

- Every product project under `src` is compiled from traced copies of its
  sources: `tools/Tlachihuani.TraceWeaver`, wired in by `Directory.Build.targets`,
  adds a `TraceLog.Enter` at every method and a `TraceLog.Step` before every
  statement. The repository's `.cs` files are not changed. Build with
  `TlachihuaniTrace=methods` for methods only, or `TlachihuaniTrace=off` for the
  original sources.
- The processes also log IPC frames, HTTP requests, processes, state changes and
  thrown exceptions, and XT logs every click, key and visible change in its
  windows. The Torrenter engine writes the same line format with
  `workers/torrent/tracing.py`, setup logs each step, and scripts use
  `scripts/script_trace.py` or `scripts/Trace-Script.ps1`.
- Keys, tokens and passwords are masked. The level is `trace` by default;
  `TLACHIHUANI_LOG_LEVEL` can lower it to `debug`, `info`, `warn`, `error` or `off`.

## Where the logs are

| Writer | Log |
|---|---|
| XT, the control tools and the setup wizard | `%LOCALAPPDATA%\XAIHT\Tlachihuani\Tlachihuani.log` |
| Scripts | `%LOCALAPPDATA%\XAIHT\Tlachihuani\script-logs` |
| Tlachihuani service | `%ProgramData%\XAIHT\Tlachihuani\logs\service.log` |
| Setup's Windows Installer actions | `%ProgramData%\XAIHT\Tlachihuani\logs\setup.log` |
| Jobs, its web facade and the Torrenter engine | `%ProgramData%\XAIHT\Tlachihuani.Jobs\logs\jobs.log`, `web.log`, `torrent.log` |
| Remote-Controller | `%ProgramData%\XAIHT\Tlachihuani.RemoteController\logs\rc.log` |

Setup creates each service's logs folder: the service can write it and the
operator can read it. A service installed before 0.38.0 writes under its state
folder instead. While XT runs it copies every new line of these logs into
Tlachihuani.log, so **Services → See log** shows the whole computer in one place;
lines written while XT was closed are copied when it starts again.
Tlachihuani.log rotates at 256 MB and keeps 40 files (about 10 GB); each service
log rotates at 256 MB and keeps 4.

**See log** opens with the newest 2 MB and follows new lines four times a second.
**Copy all** and **Open folder** remain; there is no Refresh button.

## Quiet while idle

Each polling loop (XT's status check, the services' pipe requests, the Torrenter
tick, the web health check) runs inside `TraceLog.Pass`, or `tracing.pass_scope`
in the engine. A pass identical to the previous one is not written. Any
difference, such as another branch, an error or a state change, writes the whole
pass. While nothing changes, each loop writes one line every ten minutes.

Code that runs on every repaint or several times a second is marked
`// tlachihuani:trace-off` and is not woven, for example the logger, `LogPaths`,
the log viewer, the service-log copier and XT's window painting in `StudioForm.cs`.

## Installation and packaging

The matching archive is `Tlachihuani-0.38.0-windows-x64.zip`, with its
`.zip.sha256`. The installer does not install over an existing installation:
**Stop Services**, **Exit tray**, uninstall the current Tlachihuani from
**Settings → Apps → Installed apps**, then extract everything, open
`START-HERE.html`, run Installer.exe as the same Windows user and confirm
**0.38.0** on Review. Your downloads and retained identities stay on disk. Follow
the [setup guide](../../packaging/setup/README.md).

`Directory.Build.props` and the internal project lock references declare
**0.38.0**. `Build-Release.cmd` selects the numeric `v0.38.0` tag and builds the
current checkout into `dist`. See [release building](../release-building.md).

## Evidence and remaining acceptance

- An installed build of 20 November, made before the quiet passes, showed the
  idle Torrenter tick writing about 13 lines per job row three times a second.
  That growth is what the quiet passes remove.
- On 21 November 2026 a Debug build of XT left `StudioForm.cs` untraced: its
  traced copy has no trace calls, against 125 in the previous Release build.
- Not yet tested: a 0.38.0 package build, an installed 0.38.0 package and how fast
  an idle installed system's Tlachihuani.log grows.

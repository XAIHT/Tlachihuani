# Tlachihuani 1.0.1 · Start Services with a busy Torrenter engine

**Latest version: 1.0.1, released 26 November 2026.** A fix release for
[1.0.0](v1.0.0.md), Tlachihuani's first official release; it carries everything in
1.0.0. Documentation updated as requested by Angela López Mendoza.

## Fixed in 1.0.1: Start Services no longer fails on a slow first answer

Since 0.38.0 the Torrenter engine traced every step of every generator expression,
so its first answer after a start took about 18 seconds. Jobs waited 15 seconds for
each answer, then ended the engine and its web workspace and started them again.
The restarts repeated until XT's 40-second readiness check reported a failure.

- **A slow answer means busy, not dead.** When the engine does not answer within 15
  seconds, Jobs keeps it running and discards the late reply. Only an engine that
  has owed a reply for more than 3 minutes is restarted. The startup check allows
  60 seconds.
- **The workspace stays up.** One unanswered web request is answered with 503
  (*The Torrenter engine is busy or restarting. Try again shortly.*); the web facade
  and the engine keep running. Jobs' status reply says `engine_busy` instead of
  reporting the engine as missing.
- **Less tracing work.** Generator expressions and the storage checks (`require()`)
  are no longer traced once per item. Inspecting 1,000 files went from 415,143 to
  84,041 trace entries, and from 9.6 to 1.9 seconds.
- **A gentler workspace page.** The page asks for one refresh at a time, waits up to
  30 seconds after a failure, and asks nothing while it is hidden.

See the [Torrenter guide](../torrenter.md#a-busy-engine).

## Install or upgrade

Download `Tlachihuani-1.0.1-windows-x64.zip` and its `.zip.sha256`. The installer
does not install over an existing installation, even 1.0.0: **Stop Services**,
**Exit tray**, uninstall Tlachihuani from **Settings → Apps → Installed apps**, then
extract everything, open `START-HERE.html`, run Installer.exe as the same Windows
user and confirm **1.0.1** on Review. Your downloads, retained identities and job
journal stay on disk. Follow the [setup guide](../../packaging/setup/README.md).

`Directory.Build.props` and the internal project lock references declare **1.0.1**.
`Build-Release.cmd` selects the numeric `v1.0.1` tag and builds the current
checkout into `dist`. See [release building](../release-building.md).

## Evidence and remaining acceptance

- In a visible window, with an engine slow on its first answer, installed 1.0.0
  restarted it 4 times in 75 seconds without one healthy answer. The fix kept one
  engine, healthy at 21.6 seconds, then gave 53 healthy answers. The build had 0
  errors and 26/26 worker integration tests passed.
- On 26 November 2026 the release builder built the `v1.0.1` tag (commit `4ef6b61`)
  with no local edits: 13 component checks, publish, setup and the MSI payload and
  ZIP checks passed (`artifacts/release-builds/20261127-044723-c3f7fa5b`).
- Still not tested: a clean-Windows installation and reboot of the 1.0.1 package, a
  flow pill answered by a real model, Flow Pills Terminater steps, and denial and
  cancellation of website prompts on a real phone.
- The package is unsigned; organizational approval may be required.

# HandGI windows, layout checks and the 1.0.1 package · 27 November 2026

Angela asked for an automatic layout check of HandGI's windows after the Signs window
was corrected at 150 % display scaling. The new check found three problems. They were
fixed and the whole visible suite passed again. A 1.0.1 package built from the
working tree, with HandGI, was then installed on her computer. None of this work is
committed yet.

## The layout check

`tests/Tlachihuani.HandGI.Checks` is a new console program:

```powershell
tests\Tlachihuani.HandGI.Checks\bin\Release\net10.0-windows10.0.19041.0\Tlachihuani.HandGI.Checks.exe --layout desktop
tests\Tlachihuani.HandGI.Checks\bin\Release\net10.0-windows10.0.19041.0\Tlachihuani.HandGI.Checks.exe --layout 96dpi
```

- Before any HandGI type loads it points `TLACHIHUANI_USER_DIR` at a fresh test folder
  under `%TEMP%\tlachihuani-checks`, so Angela's settings, signs and running HandGI are
  never touched.
- Its stand-in for XT counts camera requests and refuses to open the expert view,
  which turns the camera on. At the end it checks that HandGI's engine was never
  created: the camera stays off.
- On the main screen it opens **Signs**, **Camera** and **Try it** at their usual size,
  at their smallest size and again after being made smaller and bigger, the
  **Remove** question, **Teach a sign** at its usual and smallest size and with its
  camera-off note, and the volume display.
- Every window must meet the rules XT's windows meet, now shared in
  `tests/Tlachihuani.Checks/DesktopChecks.cs`: no cut or covered text, children inside
  their parents, no overlapping neighbours, check boxes and every drop-down choice
  shown in full, and nothing scrolling sideways. Only the sign list may scroll, and
  only up and down; at the usual size every sign shows without scrolling.
- The volume display must not take the keyboard: the Signs window is brought to the
  front first, and the check names any window that took the keyboard.
- Tlamatini's Shoter agent takes a whole-desktop photo of every window state.

`tests/desktop/ServicesAndHandGI.ps1` now runs it at the desktop DPI and at 96 DPI
after the Services panel layout checks.

## What it found and what changed

1. **At its smallest size the Signs page cut off hints.** Each sign's name and hint
   now get the lines they need at the current width (`SettingsForm.FitSigns`), and the
   list scrolls instead of cutting text.
2. **The volume display took the keyboard.** Windows Forms gives a `TopMost` window
   the keyboard each time it is shown. `VolumeOsd` stays in front through
   `WS_EX_TOPMOST` and `SetWindowPos(... SWP_NOACTIVATE)` instead.
3. **A drop-down drew two arrow buttons after its window was resized.** This showed
   on Teach's "What should it do?" list and the Camera list, at any DPI. HandGI's
   drop-downs now repaint whenever their size changes (`SettingsForm.Choice`).

## The 1.0.1 package with HandGI

Angela ran `Build-Release.cmd` herself from a Command Prompt.

1. **16:02, cancelled.** Ctrl+C during restore ended the run with "SDK could not be
   resolved by the SDK resolver because the worker node was shut down". That message
   came from the cancellation, not from a fault in the build.
2. **16:02, stalled.** Restore (downloading the packages the code needs) ran for more
   than 15 minutes. The builder keeps its own package folder,
   `artifacts\release-cache\packages`, and that folder had never held HandGI's
   packages: `Microsoft.ML.OnnxRuntime.DirectML` 1.24.4, `Microsoft.AI.DirectML`
   1.15.4, `Microsoft.ML.OnnxRuntime.Managed` 1.24.4, `System.Numerics.Tensors` 9.0.0
   and `Microsoft.Windows.SDK.NET.Ref` 10.0.19041.57. The download of
   `Microsoft.AI.DirectML` from nuget.org did not finish. Ctrl+C did not stop it;
   closing the window did.
3. The five packages were copied from the user's own NuGet folder,
   `%USERPROFILE%\.nuget\packages`, which already had them from development builds.
   See [release building](../release-building.md#when-restore-stalls).
4. **16:25, passed.** `artifacts/release-builds/20261127-222520-d6ba8cb5`, release
   1.0.1 from tag `v1.0.1`, checkout `35504f5` with local edits. Check and publish
   completed; 1787 runtime files and every maintenance file matched the MSI
   byte for byte, with its registration properties; the ZIP's CRC, contents,
   versions, sizes and SHA-256 hashes passed. It wrote
   `dist/Tlachihuani-1.0.1-windows-x64.zip` (16:28), replacing the ZIP built the day
   before from the clean `v1.0.1` tag. The ZIP now in `dist` therefore carries this
   uncommitted work, HandGI included.

Angela then stopped the services, exited XT, uninstalled the old Tlachihuani from
**Settings → Apps → Installed apps**, extracted the new ZIP and ran Installer.exe,
which reported **Installation complete**. **Start Services** turned XT color. HandGI
did not start with the other services because **Start with the other services** is off
in its Camera settings, as designed. **Signs…** in the HandGI section of
**Services…** started the installed HandGI and opened its Signs window; HandGI
started this way turns the camera on.
